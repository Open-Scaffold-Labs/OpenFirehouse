0. STOP — the rules this session broke, in order of cost

1. Grepping a filename is not reading the file. Check whether TODAY already solved it. Wiki anti-pattern #60, five instances in one evening. Two worth internalising:

  • I hand-rolled an OKLCH→sRGB converter and reported 38 confident false failures to Matt. 3ea090c — that same morning — records the identical mistake on the NERIS panel and its fix: let the browser convert via canvas, sanity-checked white-on-black = 21.0.
  • I escalated text-gray-400 to Matt as a design-token decision needing his ruling. The same commit had already measured it (2.60 light / 3.67 dark), chosen text-gray-500 dark:text-gray-400, and verified it (4.84 / 6.82). The decision existed, with numbers.

Before building a mechanism or escalating a decision: git log --since="3 days ago" -- <paths> and read the commit bodies — in this repo they carry the reasoning and the measurements. Before editing any file: git log -3 -- <file>.

2. A tool that writes must not describe itself as read-only. e2e/scripts/contrast-report.mjs said “reporting tool, not a gate” in its header and documented the prod BASE eleven lines above. Auditing the wizard means advancing it, and every Next runs persistStep → PATCH /api/departments/:id. It renamed prod department 1 to “Contrast Audit FD”. Restored by hand. The walk now refuses a non-localhost BASE unless ALLOW_WRITES=1.

3. Never commit a blocking gate you cannot pass. e2e.yml gates pushes AND PRs to main and calls that suite BLOCKING. I landed 09-contrast-sweep.spec.js asserting zero failures; it failed 10/10 on a real, still-open defect. A red-on-arrival gate teaches everyone to ignore a red E2E, and the nine other journeys (incident lifecycle, inspection lifecycle, tenancy isolation) lose their signal with it. It is now a ratchet with baselines written down.

4. Do not baseline from an instrument you have not validated. My first ratchet numbers came from a run where isFloating() walked to the document root, so anything under a positioned ancestor was filed uncertain. Fixing it moved 16 real dark-mode failures per surface into failures and immediately failed baselines I had written myself.

5. A silent bucket is how a defect hides. Four times in one file. See §3.

3. The auditor’s four buckets — do not collapse them

failures (normal flow, DOM backdrop IS the painted backdrop — trustworthy) · uncertain (fixed/sticky/absolute — GO LOOK) · exempt (disabled controls, WCAG 1.4.3 excludes them) · unmeasurable (native <select> chrome is OS-painted and cannot be read from the DOM at all, plus an assertion that color-scheme is declared).

Each bucket exists because that category was, at some point in one afternoon, reported as a defect or as a pass when it was neither. Known remaining limits, documented so they are not mistaken for covered cases: opacity, mix-blend-mode and backdrop-filter are ignored; color() / lab() / lch() are unparsed (they now fail closed rather than guessing). The audit’s recommendation for the parser is the canvas normaliser — which is also what 3ea090c used. Use that, not more regex.
